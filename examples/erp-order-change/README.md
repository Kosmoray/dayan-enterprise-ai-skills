# ERP 订单变更验收包

适合已经有 ERP、希望先把一个改单流程跑通的制造企业。销售收到数量或交期变更后，计划、仓库、采购和业务主管分别确认影响，再决定是否由有权限的人更新 ERP。企业微信或钉钉可作为协作入口，接口、审批方式和权限由企业实际环境决定。

本包使用演示订单 A-0245。原单为 500 件、12 月 18 日交货，客户提议改为 600 件、12 月 15 日交货。额外库存 60 件，仍有 40 件需确认排产。采购方可以用同一材料请实施团队在测试环境演示。

## 到现场怎么验

1. 请销售提交改单草案，记录新旧数量、日期、订单行和版本。让计划员说明额外 40 件与交期由谁确认，主管审批要与本版改单关联。
2. 演示审批准予后，显示订单新版本、请求号、审计记录和给相关岗位的待办。回读发现请求和结果已一致时，沿用原记录。
3. 用相同请求号重放，再分别制造版本冲突、超时和回读差异。逐项留存旧订单、审批、实际结果、处理责任人和复核时间。
4. 未审批、能力或权限未确认、版本冲突、写入状态不明时保留人工处理入口。超时或回读不一致时，先查明 ERP 里的实际状态。

## 离线复现

三个文件放在一个目录中，使用 Python 3.10 或更新版本运行。`cases.json` 附八个相互独立的测试场景。回放只计算演示状态并生成 CSV，可把结果与实施团队实际测试的证据逐项对照。

```sh
python3 replay.py > acceptance-results.csv
```

`新增模拟写入` 表示该用例预期在模拟中触发的新写入次数。实际系统还需要拿真实接口、权限、并发和失败日志验收。
