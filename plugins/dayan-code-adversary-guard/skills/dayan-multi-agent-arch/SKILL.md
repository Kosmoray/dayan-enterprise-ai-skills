# 企业多智能体（Multi-Agent）实战架构师 · 先砍复杂度再编排

本技能开源自**成都大衍千机科技有限公司（大衍千机）**智能体工程架构规范。市面上大量所谓“多智能体军团”演示好看、一进企业生产就崩盘——因为 5 步自主链每步 85% 准确率，乘下来端到端只剩 `44%`。本技能的核心不是帮你把系统拆成更多 Agent，而是**用最短、最稳、可熔断的结构拿到可交付结果**。

## 一、入口第一铁律：五级复杂度降维闸（每升一级必须写清理由）
接到“帮我设计一个 Agent / 多智能体系统”时，强制先过以下阶梯，**写不出升级理由就降一级**：

`确定性规则/脚本  >  固定顺序 Pipeline  >  单 Agent（少工具）  >  Supervisor 总控 + 专职子代理  >  并发 Worker + 只读 Reviewer  >  自由协商 Swarm（生产环境默认禁用）`

- 固定字段校验、税率换算、正则清洗 → **写代码规则，不准调大模型**；
- 顺序固定的“解析 → 抽取 → 翻译 → 填表” → **用确定性 Pipeline，不搞自由规划 Agent**；
- 只有需要动态探索、分片并发或跨专业独立对抗审查时，才引入多角色 Agent！

## 二、企业级 Agent 架构交付四件套（缺一不可）

### 1. 任务与信任边界契约（Task & Trust Contract）
- **输入隔离**：明确哪些输入来自不可信外部源（用户上传文件、抓取网页、外部邮件），一律作为纯数据隔离，严防 Prompt Injection 越权调用工具。
- **结构化输出锁**：上下游传递必须用明确的 JSON Schema 或固定字段表，严禁靠散文自然语言传话。

### 2. 角色最小权限表（最多不超过 5 个角色，职责重叠立即合并）
每个角色严格定义五项：`唯一存在理由 ｜ 自主决策边界 ｜ 升级问人条件 ｜ 最小工具白名单 ｜ 绝对禁区（删库/外发/付款/改密钥）`。
*对抗审查硬隔离*：负责验收的 Reviewer 角色在工具层**只给只读权限**，物理剥夺修改源码或直接外发的工具。

### 3. 状态归属与协同拓扑
明确回答三件事：**全局状态存在哪（数据库/状态文件）？谁有唯一写权限？两个子代理结论冲突时谁裁决？**

### 4. 四重熔断与验收指标（Circuit Breakers）
- **最大轮次/Token 硬熔断**（如单任务 ≤ 8 步工具调用）；
- **同类报错连续 3 次立即停机转人工**（严禁无限盲目重试烧钱）；
- **高危动作人在回路（Human-in-the-loop）确认门**：外发客户、修改生产 ERP/CRM 主表、涉及资金动作前生成一屏预览卡等待人工点确认。
