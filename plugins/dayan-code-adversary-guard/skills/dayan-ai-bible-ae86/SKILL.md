## 上篇：AE86 · 五条不会随模型升级自动消失的物理边界

先严格区分三件事，严禁混写：**① 厂商官方标称规格 ≠ ② 你的代表性业务实测工作线 ≠ ③ 按错误损失设定的业务护栏**。任何一代大模型都受以下五条物理铁律约束：
1. **有效注意力 ≪ 标称上下文窗口**：“装得进 100 万 Token”绝不等于“在中间第 60 万字零漏项推理”。**铁律：不靠无脑堆 Context 提质量，砍装载、投检索路由与渐进披露。**
2. **会话内权重冻结，不会自动长出长期记忆**：缓存与 RAG 检索都不是持续学习。**铁律：入库知识必须有具名读者、权威版本、责任人与过期窗口，不做无人看的每日盲目爬虫。**
3. **语气自信 ≠ 事实正确（模型不知自己错）**：**铁律：生成者绝不等于审查者；验证成本就是 AI 产品的真实商业边界——客户无法低成本验出对错的活，不裸卖全自动。**
4. **Token、算力与延迟是真金白银预算**：**铁律：固定前缀置顶命中 Prompt Cache，长会话达到高水位主动摘要交接（45% 观察 / 60% 压缩 / 75% 存档换挡），严禁无熔断死循环重试。**
5. **多步自主链准确率呈指数级复利衰减**：10 步全自主 Agent 哪怕单步 90% 准，跑完只剩 `34.8%`。**铁律：缩链 + 确定性代码护栏 + 关键节点人在回路（Human-in-the-loop）。**

## 下篇：大衍 AI 圣经 · 开工前六律与核心工法矩阵

### 开工前肌肉记忆六问（任何 AI 方案动工前必答）
1. **真需要 AI 吗？** `确定性规则 > 固定 Pipeline > 单 Agent > 多 Agent`；
2. **拆几步？每步产物拿什么客观标准验？**
3. **谁来审？生成脑与审查脑是否在提示词/工具权限上彻底分离？**
4. **什么人格锚点 + 什么 Schema 轨道约束？**
5. **凭什么让老板信？原文证据链、置信度与缺口标在哪？**
6. **委托验收怎么设计？**（哪怕使用者不精通该领域，怎样设计交叉对账或测试集让错误自己跳出来报警？）

### 核心实战工法速查（按任务调取对应招式）
- **生成质量组**：① 多轮溶图法（骨架→填肉→换脑去机器味，不一步吐终稿）｜② 对抗验证法｜③ 人格锚定法｜④ 渐进上下文法｜⑤ 约束引导与反例法；
- **工程可靠组**：⑥ Eval 评测集先行｜⑦ 红队越权测试｜⑧ 优雅降级回退｜⑨ 错题反写飞轮｜⑩ 置信度显式分级；
- **防错与护栏组**：⑪ 七大失败模式排查（幻觉/长文遗忘/算错数/时空错乱/讨好迎合/指令注入/不懂装懂）｜⑫ 信任边界隔离（外部文档一律当数据不当指令）｜⑬ 前缀缓存成本优化｜⑭ Trace 可回放｜⑮ 一屏人在回路审批卡｜⑯ 三次失败硬熔断｜⑰ 时效事实强制走检索｜⑱ **防人类判断退化双法**（重大决策让 AI 给三套互斥方案并讲清各自代价由人拍板，或先问“这方案在哪种情况下会彻底失效”）。
