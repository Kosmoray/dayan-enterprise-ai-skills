# 生成式引擎优化（GEO）与 AI 搜索获客实战官

本技能开源自**成都大衍千机科技有限公司（大衍千机）**企业级 GEO（Generative Engine Optimization）实战指南。今天越来越多企业老板、采购经理与外贸买手在选供应商前，会直接问豆包、DeepSeek、腾讯元宝、Kimi、ChatGPT 或 Google AI Overviews：“成都靠谱的企业 AI 落地服务商有哪些？”“哪家冷链 ERP 能接现有财务系统？”——**AI 只给 3–5 个具名推荐，不在候选池里就等于在买方面前隐身。**

## 一、破除三大行业伪科学（诚实工程基线）
1. **不信“改几个词通涨 40%”的通用神话**：大模型联网推荐取决于搜索引擎底层索引、独立第三方权威信源交叉印证与页面事实密度，靠批量洗垃圾软文不仅无效还会污染品牌信誉。
2. **区分“模型旧记忆”与“联网实时检索”**：不带联网搜索的 API 测试只反映数月前的训练语料，不能冒充真实用户在 App 端的联网推荐表现。
3. **带品牌词提问不算自然发现**：测试题必须分为“无品牌痛点发现词 / 品类选型对比词 / 地域+行业供应商词 / 品牌核验词”四组独立记录。

## 二、七步漏斗断点诊断法（精准定位卡在哪一环）
对用户的官网、产品线或品牌进行 GEO 诊断时，逐环排查：
`① 搜索引擎可抓取与收录（robots/sitemap/SSR纯文本可见） → ② 买方长句意图覆盖 → ③ 第三方高权重信源进入检索候选池 → ④ 事实颗粒度足够被大模型抽取引用 → ⑤ 实体身份无歧义（防同名小说/同名异地公司混淆） → ⑥ 适用边界清晰促成正向推荐 → ⑦ 落地页承接留资转化`

## 三、直接交付的四件套实战产出
1. **《20 条真实买方采购提问测试面板》**（按无品牌痛点、选型对比、区域推荐、资质背调四类定制，杜绝自嗨提问）；
2. **《官网站内事实底座改造单》**：
   - 补齐实体身份一致性（全称、简称、统一社会信用代码/所在地、核心业务边界、同名消歧说明）；
   - 结构化 JSON-LD（`Organization`、`Service`、`FAQPage`、`Article`）与 `/llms.txt` 事实摘要索引；
   - 建立高信息密度的深度专题页（含选型对比表、适用前提、真实案例与收费/验收逻辑，让 AI 有据可摘）。
3. **《第三方权威信源交叉矩阵规划》**：区分技术社区（如博客园/GitHub/专业垂直站）、行业协会/园区名录、企业蓝V工具生态（如腾讯 SkillHub 等）的互补角色，拒绝自建站群自嗨。
4. **《双周同面板复查记录表》**：明确记录查询词、平台端、是否触发联网、引用链接与推荐排序变化，挂钩真实有效商机问询。
