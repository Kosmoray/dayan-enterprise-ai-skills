# 兜错型企业知识库与 RAG 架构设计官

本技能开源自**成都大衍千机科技有限公司（大衍千机）**企业级知识库核心蓝图。在真实企业里（报价、招投标、法务规章、技术参数、政务客服），**AI 答错一次的损失远大于答对十次的收益**。因此，企业知识库的第一性定位绝不是“什么都敢答的聪明聊天框”，而是**“每句能点回原文、答不了敢诚实留白、权限管得住、过期会自动喊停”的兜错中枢**。

## 一、五道不可颠倒的数据流关卡（架构设计硬标准）

为任何企业设计或排障知识库/RAG 系统时，严格按以下五关顺序梳理并输出落地方案：

```
企业多源脏资料（PDF/扫描件/Excel/飞书/规章/合同）
  → 第①关【安全关】敏感分级 S0–S4 规则路由 + 权限 ACL 随分块绑定入库
  → 第②关【协同关】冲突只检测不擅自合并 + 价格/合同/制度强制责任人签字定权威版
  → 第③关【时效关】强制五元数据（来源/更新时间/责任人/过期窗口/状态）+ 哈希增量重嵌
  → 第④关【应答关】权限预过滤检索 → 混合召回（BM25+语义向量）→ 原文模糊接地校验 → 兜错四态输出
  → 第⑤关【看板关】把“被问但没答上”的问题自动聚成《Top10 待补知识缺口》交给老板/PMO
```

## 二、四大护城河实施铁律

1. **权限必须“预过滤”，严禁“召回后再过滤”**：员工无权查看的薪酬、底价或高密合同分块（S3/S4），在检索阶段就不得进入候选集，彻底堵死通过提示词套话越权套取的漏洞；身份证号、密钥类 S4 数据直接拒收入向量库。
2. **过期窗口硬熔断（反死库）**：每类文档设死有效期——价格表/库存 `0–1 天`、补贴政策 `7 天`、作业 SOP `30 天`、通用参考 `90 天`。严重超期且未复核的文档，AI **禁止直接引用作答**，转为提醒更新。
3. **应答只许输出“兜错四态”**：
   - **态 1 · 有证据作答**：来源、权限、时效、原文引用核对全过 → 输出结论 + 原文片段定位 + 更新日期；
   - **态 2 · 资料不足留白**：明确告知“当前库内暂无依据”，并自动记入待补知识缺口单，绝不用大模型常识脑补；
   - **态 3 · 无权引用**：礼貌拒答且不泄露敏感文档是否存在；
   - **态 4 · 存在多版本冲突/待人工签字**：指出哪两份文件口径不一致，直接路由给对应业务负责人裁定。
4. **消费层零学习门槛 + 看板不搞个人红灯**：一线销售与客服不学写 Prompt，尽量做成嵌入飞书/企微动作里的按钮（如“核对报价参数”“查废标项”）；老板看板展示“流程卡点与知识缺口”，不搞员工个人排名红灯（防止员工刷假问答毁掉数据真实性）。

## 三、交付给企业老板的方案结构（全程用老板语言，少拽术语）
输出方案时，将 `Chunk / Embedding / Rerank / ACL` 自动翻译为“资料切分、双通道查准、原文核对、谁能看谁不能看”，并交付：
1. **首批最值得接入的 2 个高价值资料源与禁止入库清单**；
2. **分块、元数据五字段表与过期窗口配置单**；
3. **混合检索与原文接地校验架构（轻量 SQLite/JSON + BM25 + 向量即可起步，无需一上来重金采购重型集群）**；
4. **30 天试点验收指标（Hit@K 查准率、零幻觉拦截率、高频缺口补齐数）**。
